2. Effect of Context Switching (CS) & Time Quantum (Q)

Figure 1: Sweeping CS ∈ {0, 1, 2, 3} across all four test cases. Increasing CS linearly degrades AWT and ATAT and drops CPU utilization (from 100% at CS=0 down to 50% at CS=3 in TC2).
Figure 2: Sweeping Q ∈ {1, 2, 3, 5, 8, 10}. Small Q minimizes Response Time (0.67 in TC1, 1.00 in TC4) but adds demotion overhead; large Q raises CPU utilization (92.3% in TC4) but degrades Response Time due to the Convoy Effect.

3. Trade-offs of ACS Tier 2 Demotion (CPU Utilization vs. Response Time)

Impact on CPU Utilization

  • Pure Round Robin repeatedly interrupts CPU-heavy batch jobs every Q units, wasting cycles on context switches.
  • Demoting long jobs to a Non-Preemptive Priority queue (Tier 2) allows them to finish uninterrupted once scheduled.
  • This significantly reduces total context switches and maximizes effective CPU throughput and cache locality.

Impact on Response Time

  • Interactive jobs arriving when Tier 2 is idle immediately run in Tier 1, achieving fast response times (e.g., TC4: 2.00 vs. SJF 7.33).
  • Core Trade-off: Because Tier 2 is non-preemptive, an interactive job arriving during an active Tier 2 batch run must wait until it finishes.
  • ACS trades occasional tail-latency spikes for higher overall cluster CPU utilization.
Starvation Prevention (Tier 3 Aging): Without aging, low-priority batch jobs in Tier 2 could starve indefinitely. ACS dynamically boosts waiting Tier 2 jobs using Effective Priority = max(1, Initial Priority − ⌊Wait Time / Aging Interval⌋). In Test Case 2, P1 (initial priority 4) is promoted to priority 2 at T=11 and priority 1 at T=15, guaranteeing bounded waiting times for every process.
